## 1. 背景

### 1.1 現状

- セーブデータは IndexedDB（`idb` ライブラリ）でブラウザローカルに保存。データ構造は `{ creatures: Creature[], activeCreatureId: string | null }`
- ファイルエクスポート / インポート（File System Access API + anchor フォールバック）で手動バックアップが可能。サイズ上限 1 MB
- 認証基盤・ネットワーク通信はゼロ。完全クライアント完結型 PWA（GitHub Pages ホスティング）
- ブラウザキャッシュ削除・機種変更でデータ消失のリスクあり

### 1.2 やりたいこと

Google アカウントでサインインし、セーブデータをクラウドに自動同期できるようにする。
異なるデバイスで同じデータを引き継げること、誤消去時のリカバリが目的。

スコープ外（将来）: 複数セーブスロット、セーブ履歴・ロールバック、ソーシャル機能

---

## 2. ゴール

### 2.1 主目的

- Google アカウント 1 つでどのデバイス・ブラウザからでも同じセーブデータでプレイできる
- ターゲット値: デバイス変更後のデータ引き継ぎ率 100%（クラウド同期が正常動作している場合）

### 2.2 副次目的

- クラウド自動バックアップによる誤消去リスクの排除
- 将来のクロスデバイス機能（将来のリーダーボード・フレンドバトル等）の認証基盤整備
- サインイン不要の既存プレイ体験を維持（ゲスト継続プレイが可能）

---

## 3. スコープ

### 3.1 含むもの

- Google Sign-In（Firebase Authentication）の組み込み
- セーブデータの Firestore 同期（読み取り・書き込み）
- サインイン / サインアウト UI（ヘッダー or 設定画面）
- 同期ステータス表示（最終同期日時・同期中インジケーター）
- コンフリクト解決ロジック（タイムスタンプ比較）
- 既存のファイルエクスポート / インポート機能を削除（クラウドセーブに一本化）

影響ファイル概略: `src/services/`, `src/hooks/`, `src/components/`, `.env`, `package.json`

### 3.2 含まないもの

- 複数セーブスロット管理
- セーブ履歴・ロールバック
- メールアドレス / パスワード認証（Google のみ）
- サーバーサイドロジック（バックエンドサーバー追加なし）
- Firebase Hosting への移行（GitHub Pages を維持）

---

## 4. 機能要件

### 4.1 認証フロー

1. 「Googleでサインイン」ボタンをタップ → Google OAuth ポップアップ（または リダイレクト）起動
2. Google 認証完了 → Firebase Auth トークン取得
3. 初回サインイン時: Firestore にセーブデータが存在しない → ローカルデータをアップロード
4. 再サインイン時（別デバイス）: Firestore のデータをダウンロードし、ローカルと比較 → 新しい方を採用（タイムスタンプ比較）
5. コンフリクト（タイムスタンプ差が小さい場合）: どちらを使うかユーザーに選択肢を提示
6. サインアウト: Firebase Auth からサインアウト → ローカルデータはそのまま保持

### 4.2 同期仕様

- **自動同期**: セーブデータ変更時に Firestore へ書き込み（デバウンス 3 秒）
- **手動同期**: 同期ボタンで即時同期
- **起動時同期**: アプリ起動時にサインイン済みであれば Firestore から最新データを取得
- Firestore パス: `users/{uid}/saveData`
- ドキュメント構造: `{ creatures: Creature[], activeCreatureId: string | null, lastSyncedAt: number }`

### 4.3 既存機能の互換要件

- サインインしていないユーザーは従来通り IndexedDB ローカルで完全プレイ可能

## 5. 非機能要件

### 5.1 パフォーマンス

- バンドルサイズ増加: Firebase モジュラー SDK（tree-shake 後）で +50 KB gzip 以内
- 初回ロード後の同期レイテンシ: < 3 秒（Firestore SDK の初回接続含む）
- 自動同期のデバウンス: 3 秒（過剰な書き込み防止）

### 5.2 信頼性

- Firestore 書き込み失敗時は UI でエラー表示し、次回起動時に再試行
- Firebase SDK の接続タイムアウト: デフォルト（Firebase 側が管理）

### 5.3 互換性・依存

- フロント: Firebase SDK v9 モジュラー（`firebase/app`, `firebase/auth`, `firebase/firestore`）を追加
- 対応ブラウザ: Chrome / Safari / Firefox / Edge 最新 2 バージョン（変更なし）
- **ハードコーディング禁止**: Firebase プロジェクト設定（apiKey, projectId 等）はすべて `VITE_FIREBASE_*` 環境変数経由で取得

### 5.4 セキュリティ

- Firebase Security Rules で `users/{uid}/saveData` を `uid == request.auth.uid` で保護（他ユーザーのデータは読み書き不可）
- Google OAuth は Firebase Auth 経由（トークン管理は Firebase SDK に委任）
- Firestore に書き込む Creature データのサイズ上限バリデーション（1 MB）
- ユーザーデータ削除機能: サインアウト時または設定から「クラウドデータを削除」が可能

---

## 6. 制約・前提条件

- Firebase プロジェクトは別途シャビが Firebase Console で作成する（Spark プラン / 無料）
- GitHub Pages での HTTPS 配信は維持（OAuth に必須）
- バックエンドサーバーは追加しない（Firebase SDK のみでフロントエンド完結）
- Firebase Security Rules の設定は実装タスクに含む
- GDPR / 個人情報保護法: ユーザーデータはゲームセーブデータのみ。プライバシーポリシーの整備は今回スコープ外

## 7. 受け入れ条件

- [ ] 未サインイン状態でも従来通り IndexedDB ローカルでゲームが動作する
- [ ] ファイルエクスポート / インポート UI が削除されている
- [ ] Googleアカウントでサインインできる
- [ ] サインイン後、セーブデータが Firestore に自動同期される
- [ ] 別デバイス（同アカウント）でサインインするとクラウドのデータが引き継がれる
- [ ] `npm run build` が成功し、バンドルサイズ増加が +50 KB gzip 以内
- [ ] クルトワ（security-engineer）レビューで Critical/High なし
