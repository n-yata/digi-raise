## 1. 背景

### 1.1 現状

成長は「ゲーム内30分ティック ≒ 実時間30分」で進む（`applyTimeUpdate`、`src/utils/gameLogic.ts:123`）。
年齢は実時間1時間ごとに +1（`age += thirtyMinTicks * 0.5`）と速く、おなかは**時間でも行動でも**減る
（`applyTimeUpdate` で `-5/ティック`、トレ `-10`、遊ぶ `-5`）。テンポが速く「育てている実感」が薄い。
進化条件 `EVOLUTION_REQUIREMENTS`（`src/data/evolutions.ts:80`）は年齢を時間単位（1/3/6/12）で見ている。

### 1.2 やりたいこと

成長を**現実時間ベースの落ち着いた育成**へ作り替える。年齢は現実1日で+1歳、おなかは時間経過のみで
約8時間で空腹（1日3回の食事ペース）、新しい裏パラメータ「疲労度」を追加してトレ・遊ぶの乱用を抑える。

---

## 2. ゴール

### 2.1 主目的

- 年齢を **現実1日 = +1歳** にして、育成を現実の生活リズムに沿わせる。
- おなかを **時間経過のみ**・約8時間で 100→0（1日3回の食事ペース）にする。
- 裏パラメータ **疲労度** を導入し、疲労MAXでトレ・遊ぶを実行不可にする。
- ターゲット値（参考）: 年齢 +1/1時間 → **+1/1日**、おなか −240/日（時間＋行動）→ **時間のみ −300/日相当（約8h空腹）**。

### 2.2 副次目的

- 疲労を「クリーチャーのモーション」で見せることで、数値に頼らない情緒的フィードバックを得る。
- 進化を日数スケールにすることで、長期育成の達成感を作る。

---

## 3. スコープ

### 3.1 含むもの

- 年齢加算レートの変更（現実1日 = +1歳）。
- おなか減少を**時間経過のみ**に変更（トレ・遊ぶのおなか消費を撤廃）、約8時間で空腹。
- 裏パラメータ `fatigue`（0–100）の新設：トレ +15 / 遊ぶ +10、時間経過で常時回復（約3時間で全回復）、
  MAX(100)でトレ・遊ぶ不可、60以上で「疲労中」モーション。
- 進化条件 `EVOLUTION_REQUIREMENTS` の minAge を日数へ再スケール（0.5 / 1 / 3 / 7 日）。
- 影響ファイル概略: `src/types/creature.ts`, `src/utils/gameLogic.ts`, `src/data/evolutions.ts`,
  `src/utils/storage.ts`, `src/components/ActionButtons.tsx`, `src/components/CreatureSprite.tsx`,
  および対応テスト（`gameLogic.test.ts` / `useTimeUpdate.test.ts` / `evolution.test.ts`）。
- 維持する既存機能: feed(+30)、幸福度効果、睡眠/照明、HP回復、餓死ダメージ、オフライン復帰の追いつき計算。

### 3.2 含まないもの

- 疲労度のUIバー・数値表示（**非表示**。モーションのみで表現）。
- 既存セーブの age 値マイグレーション（旧「時間」値を「日」として扱う。Q1で最終確認）。
- ダメージ計算式・タイプ相性・EXP/ステータス成長量・special効果の変更。

---

## 4. 機能要件

### 4.1 時間更新（applyTimeUpdate）

30分ティック構造（本番30分/dev30秒）は維持し、レートのみ差し替える。

1. 年齢: `age += thirtyMinTicks / 48`（48ティック=24h で +1歳）。
2. おなか: `hunger -= thirtyMinTicks * 6.25`（16ティック=8h で 100→0、下限0）。
3. 疲労回復: `fatigue = max(0, fatigue - thirtyMinTicks * (100/6))`（6ティック=3h で全回復）。
4. 幸福度減少・照明ミスマッチ・HP回復・餓死ダメージ・睡眠同期は現状のまま。

### 4.2 アクション・データモデル

| 項目 | 仕様 |
|------|------|
| `Creature.fatigue` | number（0–100）、新規。既定0。レガシーセーブは `fatigue ?? 0` |
| trainCreature | おなか消費を撤廃、`fatigue += 15`。幸福度 −5・EXP・ステ成長は維持。`fatigue >= 100` なら no-op |
| playWithCreature | おなか消費を撤廃、`fatigue += 10`。幸福度効果は維持。`fatigue >= 100` なら no-op |
| feedCreature | 現状維持（+30、上限100） |
| ActionButtons | `fatigue >= 100` でトレ・遊ぶボタンを無効化 |
| getAnimationState | `fatigue >= 60` で `'tired'` を返す（既存の優先順位に組み込む） |
| CreatureSprite | `'tired'` モーションを描画 |

### 4.3 進化条件の再スケール（minAge、日数）

| stage | 遷移 | 現状(時間) | 新(日) |
|-------|------|-----------|--------|
| 0 | egg→baby | 0 | 0（即時・維持） |
| 1 | baby→child | 1 | 0.5 |
| 2 | child→adult | 3 | 1 |
| 3 | adult→perfect | 6 | 3 |
| 4 | perfect→ultimate | 12 | 7 |

happiness/level/combatStats など年齢以外の条件は変更しない。

### 4.4 既存機能の互換要件

- オフライン復帰時の追いつき計算（`elapsed / thirtyMinutes`）の仕組みは維持。
- 既存セーブが**エラーなくロード**できること（`validateCreature` が fatigue を許容）。
- 睡眠/照明/HP回復/餓死の挙動は現状維持。

---

## 5. 非機能要件

### 5.1 パフォーマンス

- ティック処理は現状同様 O(1)。追加コストは fatigue 計算のみで体感影響なし。

### 5.2 信頼性

- fatigue は常に 0–100 にクランプ。age/hunger も既存同様クランプ・型安全を維持。
- レガシーセーブ（fatigue 欠落）でクラッシュしない。

### 5.3 互換性・依存

- フロント: 追加依存なし（React + Vite + TS の既存スタックのみ）。
- バックエンド: 対象外（フロント単独）。
- ハードコーディング禁止: 数値定数は `gameLogic.ts` に名前付き定数で集約（`FATIGUE_MAX` 等）。マジックナンバー散在を避ける。

### 5.4 セキュリティ

- 外部入力・通信・認証への影響なし。セーブデータの数値検証（`validateCreature`）に fatigue を追加。
- URL/シークレット等のハードコーディングは持ち込まない。

## 6. 制約・前提条件

- 30分ティック構造を踏襲（大規模な時間更新アーキテクチャ変更はしない）。
- ゲームデザイン数値はシャビ承認済み（年齢=1日/歳、進化=標準スケール、疲労=ゆるめ、おなか=約8h空腹）。
- プロセス制約: コミット前にクルトワ（security-engineer）レビュー必須。実装は worktree + feature ブランチ + PR 経由。

---

## 7. 受け入れ条件

- [ ] 行動なしで現実24h経過（オフライン復帰）で age が +1 される。
- [ ] 行動なしで約8時間でおなか 100→0。トレ・遊ぶはおなかを**変えない**。
- [ ] feed で +30 回復（上限100）。
- [ ] トレで fatigue +15、遊ぶで +10。`fatigue=100` で両ボタン無効＆関数は no-op。
- [ ] トレ/遊ぶをやめて約3時間で fatigue が 0 へ回復。
- [ ] `fatigue>=60` でクリーチャーが疲労モーションになる（UIに数値・バーは出ない）。
- [ ] 進化が新しい日数しきい値（0.5/1/3/7）でゲートされる。
- [ ] 既存セーブがエラーなくロードできる（fatigue 既定0、age は既存値を保持）。
- [ ] `npm run build` / `npm run lint` / `npm run test:run` がパス。
- [ ] クルトワ（security-engineer）レビューで Critical/High なし。
