# 実装後の振り返り

## 作業概要

クリーチャーが SVG（ベクター）化されレトロなドット絵感を失っていた問題を、**32×32 の本物のドット絵スプライトへ全面移行**して解決した。汎用レンダラ `PixelSprite`（文字グリッド+パレット→`<rect>`）を土台に、`buildTypePalette()` でベース色から陰影を自動生成し、6タイプ×5ステージ=30体を量産。未登録は従来 SVG にフォールバックする無停止移行とした。

## 実装完了日

2026-06-20

## 計画と実績の差分

**計画と異なった点**:
- 当初はモザイクフィルタ（SVG `feTile`/`feMorphology`）で「SVGをドット絵風に見せる」案を試作したが、ドットの目が揃わずシャビ却下。本物のドット絵スプライトを新規作成する方針へ転換（decisions.md D-001）。
- 解像度はプロトの体感を経て 32×32 に確定。進め方は Fire 1体プロト先行 → 承認 → 量産、という段階を踏んだ。

**新たに必要になったタスク**:
- `palette.ts` のパレット生成ヘルパー新設（プロトの手書きパレットを HSL シフト規則に分解して一般化）。これにより 30体の色を1箇所へ集約しハードコーディングを排除。
- グリッド整合性の機械検証（行32×32・許可文字）。量産をサブエージェント並列で行ったため、中央での再検証が品質の要になった。

**技術的理由でスキップしたタスク**: なし（全タスク完了）。

## 学んだこと

**技術的な学び**:
- **SVG はそのままではドット絵にならない**。`shapeRendering="crispEdges"` + 1セル=1`<rect>` の素朴な描画が、フィルタによるモザイク化より遥かにきれいなレトロ表現になる。
- **陰影は HSL シフトで規則化できる**。プロトの実測色（影=彩度×0.76〜0.84、ハイライト=色相+10°/L+11）を `buildTypePalette()` に落とすと、ベース色1つから一貫した陰影パレットが作れ、タイプ間のブレも消えた。
- **フォールバック設計が無停止移行を可能にする**。`getPixelSprite()` が null を返すと従来 SVG に落ちるため、タイプ単位の部分リリースでも画面が壊れない。
- **dev サーバーの落とし穴**: ファイル編集の中間状態を vite HMR が掴むとスタックすることがある（`palette is not defined` のゴーストエラー）。本番ビルドは常に正常だったため、dev 再起動で解消。HMR エラーは必ず `npm run build` で真偽を切り分ける。

**プロセス上の改善点**:
- 量産フェーズをタイプ別にサブエージェント6体へ並列分担し、各自に「自己検証（行長・文字種）が緑になるまで直す」を課したことで、中央の手戻りを最小化できた。
- 共通シルエットテンプレ（design.md §3.3）と教科書スプライト（`fireAdult.ts`）を先に固めたことで、並列でも体格・塗り分けの一貫性が保てた。

## 次回への改善提案

- ドット絵の「見た目の良し悪し」は最終的にゲームデザイン判断。量産前にプロト1体で方向性を握る今回の進め方は有効だった。今後タイプ追加時も同様にプロト先行を推奨。
- 将来、表情の state 差し替え（happy/attack 等）を入れる場合は、design.md §10 Q2 の `overlays?` 方式（目/口の差分グリッドのみ重ねる）で後方互換に追加できる。本体グリッドの作り直しは不要。
- 多数同時表示で rect 数が問題化したら、`PixelSprite` 内に水平ラン圧縮を閉じて入れる（データ契約は不変）。
