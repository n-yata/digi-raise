## 1. 背景

### 1.1 現状

- クリーチャーは SVG（楕円・円ベースのベクター）で描画されており（`src/components/creatures/`）、アンチエイリアスで滑らかに表示されるため、以前のレトロなドット絵感が失われていた。
- 暫定対応として SVG にモザイクフィルタ（`#retro-pixelate`）をかける案を試したが、ドットの目が揃わず「ごまかし」になるためシャビ却下（[decisions.md](./decisions.md) D-001）。
- 32×32 グリッドの本物のドット絵スプライトをゼロから作る方針に決定。汎用レンダラ `PixelSprite` と Fire 成長期（stage 3）のプロトを実装し、**シャビ承認済み**。

### 1.2 やりたいこと

- 全クリーチャー（6タイプ × 5ステージ = 30体）を 32×32 のドット絵スプライトへ移行し、レトロなドット絵表示に統一する。
- 移行は `getPixelSprite()` のフォールバック機構で段階的に行い、未移行分は従来SVGのまま共存させる。

---

## 2. ゴール

### 2.1 主目的

- 30体すべてが 32×32 ドット絵で表示され、`shapeRendering="crispEdges"` でドットがくっきり描かれる。
- タイプごとに一貫した配色・テーマ、ステージごとに成長を感じる体格差を持つ。

### 2.2 副次目的

- 文字グリッド + パレットというデータ駆動の基盤により、今後のクリーチャー追加・調整が容易になる（DX 改善）。
- フォールバック機構により、移行途中でもアプリが常に動作する（無停止移行）。

---

## 3. スコープ

### 3.1 含むもの

- 量産基盤の確定（バルベルデ設計）: 共通パレット方針、ステージ別の体格テンプレ、ファイル/ディレクトリ構成、型。
- ドット絵データ 30体: Fire / Water / Plant / Thunder / Dark / Light × Baby(1)/Child(2)/Adult(3)/Perfect(4)/Ultimate(5)。
  - Fire 成長期(3) はプロト済み。残り 29体を作成。
- `getPixelSprite()` の対応表を全タイプ×全ステージに拡張。
- スプライトデータの整合性テスト（ギュレル）: 全グリッド 32×32、palette キー網羅、未定義文字の検出。
- 既存の CSS アニメーション（`animate-*`、ラッパー div の transform）が引き続き機能すること。

### 3.2 含まないもの

- 卵（stage 0 / `EggBody`）のドット絵化 — 別途検討（今回は現状維持）。
- アニメーション state（happy/attack/sleeping 等）ごとの**表情差し替え**の本格対応 — 方針は未確定事項で協議（§8 Q2）。プロト同様まず静止1枚を基本とする。
- バトル画面・進化演出のロジック変更（表示の差し替えのみで完結させる）。
- 新しい進化系統・ステータス・バランスの変更（ゲームデザインには一切触れない）。

## 4. 機能要件

### 4.1 スプライト表示フロー

1. `CreatureSprite` が `type` / `stage` から `getPixelSprite(type, stage)` を引く。
2. ドット絵データがあれば `PixelSprite`（32×32、`crispEdges`）で描画。
3. 無ければ従来の `DefaultCreatureBody`（SVG）にフォールバック。
4. ラッパー div の CSS アニメーション（跳ねる・揺れる等）は従来通り適用される。

### 4.2 データモデル

| 項目 | 内容 |
|------|------|
| グリッド | 32行 × 32文字（`PixelSpriteData.grid`） |
| パレット | 文字 → 色（`PixelSpriteData.palette`）。未定義文字は透明 |
| 配置 | `src/components/creatures/pixel/<type><Stage>.ts`（例: `fireAdult.ts`） |
| 登録 | `src/components/creatures/pixel/index.ts` の `PIXEL_DISPATCH` |

### 4.3 既存機能の互換要件

- 既存の `CreatureSprite` の props（`type` / `stage` / `animState` / `customSvg`）は変更しない。
- お絵描き（`customSvg`）機能は従来通り優先される。
- 影・Zzz・！などの装飾オーバーレイは維持。

---

## 5. 非機能要件

### 5.1 パフォーマンス

- 1スプライトの描画は塗りつぶしセルのみ `<rect>` 化（透明セルは描かない）。バトル時の同時2体表示でもカクつかないこと。
- 必要なら同色の水平連続セルを1つの `<rect>` にまとめる最適化を検討（design.md）。

### 5.2 信頼性

- 未移行・データ不整合時は従来SVGへフォールバックし、画面が壊れないこと。

### 5.3 互換性・依存

- フロント: 追加ライブラリなし（React + SVG のみ）。
- ハードコーディング禁止: 色はパレット定数に集約。マジックな閾値・URL等は持たない（純粋な表示データ）。

### 5.4 セキュリティ

- 表示専用データのみ。外部入力・ユーザー入力を描画に流用しない（`customSvg` は既存の DOMPurify 経路を変更しない）。

## 7. 受け入れ条件

- [ ] 6タイプ × 5ステージ = 30体すべてが 32×32 ドット絵で表示される
- [ ] 各スプライトのグリッドが厳密に 32行×32文字である（テストで保証）
- [ ] palette に存在しない文字（透明扱いを除く）が混入していない（テストで保証）
- [ ] 既存の CSS アニメーション・装飾オーバーレイが従来通り動作する
- [ ] `npm run build` / `npm run test:run` が通る
- [ ] クルトワ（security-engineer）レビューで Critical/High なし

## 8. 未確定事項（design.md でバルベルデと協議）

- Q1. **共通パレット方針**: `TYPE_COLORS` のベース色から影/ハイライトを自動生成するか、タイプ別に手調整パレットを持つか。レトロ感と発色のバランスをどう取るか。
- Q2. **表情/アニメ state 対応**: ドット絵を state ごと（happy/attack/sleeping…）に差し替えるか、静止1枚で割り切るか、目/口だけ小さなオーバーレイで切り替えるか。
- Q3. **ステージ別の体格テンプレ**: Baby〜Ultimate の大きさ・シルエットの方向性（共通の基準シルエットを設けるか、タイプごとに自由に描くか）。
- Q4. **描画最適化**: セル単位 `<rect>` のままでよいか、水平ラン圧縮や `<image>`(data URI) 化まで踏み込むか。
