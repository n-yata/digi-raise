## 学び・申し送り

### 1. 引き継ぎサマリーと実ドキュメントの不一致に注意
セッション引き継ぎサマリーは「トレーニングは反射神経ミニゲームをスコア制で残す」と記述していたが、
実際の承認済み設計（`decisions.md` D-1〜D-4、シャビ承認あり）は **3アクション全て即時化・ミニゲーム全廃**だった。
CLAUDE.md の「サマリーを信頼しない」原則に従い、実ファイル（decisions.md / tasklist.md）を正として進めたことで矛盾を回避できた。
→ 引き継ぎ時は必ず `.steering/` の実ドキュメントを Read で確認してから着手すること。

### 2. dangling import の残り火
ミニゲームコンポーネント削除後、`App.tsx` に `TrainingMiniGame` の未使用 import が1行残っていた。
ビルド前に grep で参照確認 → 除去して build グリーンを確認した。
→ コンポーネント削除時は import 行の除去まで1セットで確認する。

### 3. preview_eval での React 状態検証は「クリックと読み取りを別呼び出しに分ける」
ボタン `.click()` と `document.body.innerText` の読み取りを同一 eval 内で同期実行すると、
React の再描画前の古い値を拾ってしまう。クリックと状態読み取りは別々の eval 呼び出しに分けると安定する。
→ 実機検証ではアクション発火と結果確認のラウンドトリップを分離する。

### 4. セキュリティレビューは decisions.md も渡すと精度が上がる
クルトワが「失敗分岐の消滅＝バランス変更では」と Low 指摘したが、これは decisions.md D-2/D-3 で承認済みだった。
レビュー依頼時に decisions.md の承認状況も併せて共有すれば、確認済み事項の再指摘を減らせる。
