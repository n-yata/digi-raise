---

## 1. 背景

### 1.1 現状

ごはん・トレーニング・遊びの各アクションは、メイン画面のボタンを押すと
それぞれ全画面モーダルのミニゲーム（`FeedMiniGame` / `TrainingMiniGame` / `PlayMiniGame`）へ
遷移し、ミニゲームをこなした結果がステータスに反映される。
トレーニングと遊びはミニゲームの成否で効果量が変わる（成功/失敗の2分岐）。

### 1.2 やりたいこと

ミニゲームへの遷移を廃止し、メイン画面のままボタン1タップでアクションが即発動するようにする。
バトル・ステータス・寝る等の他アクションは現状維持。

---

## 2. ゴール

### 2.1 主目的

- ごはん・トレーニング・遊びを **メイン画面の状態のまま** 1タップで実行できる
- 画面遷移（モーダル）が一切発生しない快適な育成操作にする

### 2.2 副次目的

- ミニゲーム3コンポーネントを削除しコードベースを軽量化
- 操作フローの単純化により将来のアクション追加が容易になる

---

## 3. スコープ

### 3.1 含むもの

- `src/App.tsx`: feed/train/play ハンドラを即時実行へ変更、ミニゲーム関連 state / import / 描画を削除
- `src/components/FeedMiniGame.tsx` / `TrainingMiniGame.tsx` / `PlayMiniGame.tsx`: 削除
- 既存の効果量ロジック（`gameLogic.ts` の `feedCreature` / `trainCreature` / `playWithCreature`）は**維持**

### 3.2 含まないもの

- 効果量・成長値・EXP・タイプ相性などゲームバランス数値の変更（一切しない）
- バトル / ステータス / 寝る / 進化 フローの変更
- `ActionButtons.tsx` のボタン構成変更（disabled 条件含め現状維持）

---

## 4. 機能要件

### 4.1 ユーザーフロー（変更後）

1. ユーザーがメイン画面で「ご飯」をタップ → 満腹（hunger>=100）でなければ即 `feedCreature` を適用しメッセージ表示
2. ユーザーがメイン画面で「トレーニング」をタップ → 即 `trainCreature(c, true)` を適用（常に成功扱い）、攻撃アニメ＋成功メッセージ
3. ユーザーがメイン画面で「遊ぶ」をタップ → 即 `playWithCreature(c, true)` を適用（常に成功扱い）、成功メッセージ
4. いずれもモーダル遷移は発生しない

### 4.2 成否の扱い

| アクション | 成否 | 効果量 |
|-----------|------|--------|
| ごはん | 成否概念なし（従来通り） | `feedCreature` |
| トレーニング | 常に成功（`success=true`） | `trainCreature(c, true)` |
| 遊び | 常に成功（`success=true`） | `playWithCreature(c, true)` |

### 4.3 既存機能の互換要件

- `feedCreature` / `trainCreature` / `playWithCreature` のロジックは変更しない
- ごはんの「満腹で食べられない」ガード、トレ/遊びの「睡眠中・空腹0は不可」ガードは維持
- localStorage 永続化（`persistActiveCreature`）の挙動は維持

---

## 5. 非機能要件

### 5.1 パフォーマンス

- 即時反映のため体感レスポンスはむしろ向上。`npm run build` のバンドルサイズはミニゲーム削除分減少。

### 5.2 信頼性

- アクション後も既存同様 localStorage へ即保存。例外時挙動の変更なし。

### 5.3 互換性・依存

- フロント: React + Vite + TypeScript。追加依存なし。
- ハードコーディング禁止: 本変更で新規の URL/シークレット/数値定数の追加なし。

### 5.4 セキュリティ

- 外部通信・入力処理の追加なし。XSS 等の新規攻撃面なし（コミット前にクルトワレビュー）。
