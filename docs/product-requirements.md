## 1. 背景・課題

90年代に流行したデジモン風の携帯育成ゲームへのオマージュとして、Web ブラウザだけで遊べる軽量な育成バトル PWA を作る。
追加インストールなしで気軽に触れて遊べるゲームを、個人運用可能なスモールサイズで提供することを目指す。

---

## 2. ゴール・目的

| フェーズ | ゴール |
|---------|--------|
| MVP | 1人プレイで卵→アルティメットまでの育成と進化が完結し、CPU バトルで遊べる |
| 拡張 | 複数クリーチャー管理・進化時お絵描き・ミニゲーム刷新等の周辺機能を充実 |

**成功基準（MVP）:** GitHub Pages に公開され、シャビと友人がスマホ/PC ブラウザで遊べる状態。

---

## 3. スコープ

### 対象範囲

- クリーチャーの育成（ごはん・トレーニング・あそぶ・ねる・成長・進化・死亡）
- 進化のたびのお絵描き機能（64×64 ピクセルアート、SVG 保存）
- 複数クリーチャー管理（最大5体、墓石含む）
- バトルシステム（CPU 戦）
- セーブデータ管理（IndexedDB 永続化、JSON エクスポート/インポート）
- PWA としてのインストール対応（Service Worker + Manifest）

### 対象外

- オンライン対戦（バックエンド削除につき非対応）
- ユーザーアカウント・ログイン機能
- リアルタイムランキング・リーダーボード
- ゲーム内課金・広告
- ネイティブモバイルアプリ（PWA でカバー）
- 個人情報の収集・分析

## 5. 機能要件

| # | 機能名 | 概要 | 優先度 |
|---|--------|------|--------|
| F-001 | クリーチャー育成 | ごはん・トレーニング・あそぶ・ねるで世話。満腹度/しあわせ度/HP/EXP/atk/def/spd/重さを管理 | Must |
| F-002 | 進化システム | age・level・ステータス条件を満たすと自動進化（タマゴ→ベイビー→チャイルド→アダルト→パーフェクト→アルティメット） | Must |
| F-003 | 6タイプのクリーチャー | Fire/Water/Plant/Thunder/Dark/Light の6タイプ、最終進化名と特色（連撃/回復/毒/麻痺/デバフ/防御バフ）が異なる | Must |
| F-004 | 進化時のお絵描き | 進化のたびに 64×64 ピクセルキャンバスで姿を手描き、SVG として保存・表示 | Should |
| F-005 | 複数クリーチャー管理 | 最大5体（墓石含む）保有、ステータス画面から切替・個別削除。非アクティブは時間停止 | Must |
| F-006 | 死亡・墓石 | hunger 0 で餓死ダメージ、HP 0 で死亡し墓石としてリストに残る | Must |
| F-007 | CPU バトル | オフラインで遊べる対 CPU バトル、CPU はランダムにアクション選択 | Must |
| F-008 | バトル中の特殊技 | タイプ別 special アクション（クールダウン2ターン）。連撃・回復・毒・麻痺・デバフ・防御バフ | Must |
| F-009 | ミニゲーム | トレーニング（もぐらたたき）・あそぶ（神経衰弱）・ごはん演出 | Must |
| F-010 | セーブ・ロード | IndexedDB 永続化、JSON ファイルでエクスポート/インポート（旧形式の後方互換あり） | Must |
| F-011 | PWA インストール | Service Worker + Manifest でホーム画面追加可能 | Should |

## 6. 非機能要件

### パフォーマンス

- フロントエンド初回ロード: LCP 2.5s 以下（GitHub Pages + Service Worker キャッシュ）
- バトル中は 60fps 維持
- バンドルサイズ目標: 初回ロードで gzip 250KB 以下

### セキュリティ

- カスタム SVG（ユーザー描画）はエクスポート時に除外し、XSS 経路を増やさない
- `dangerouslySetInnerHTML` を使わない（React の自動エスケープに依存）

### 可用性

- 動作環境: 公開はインターネット必須。育成と CPU バトルはオフラインでも継続可能（Service Worker）
- アップタイム目標: 個人運用のためベストエフォート（明示 SLO は設けない）

### 保守性

- フロントエンド単体でのモノリシック構成
- creature データはフロントエンド完結の IndexedDB で管理し、スキーマ変更は移行関数（`migrateLegacyData`）で対応

### 拡張性

- 新タイプ・新進化系統は `frontend/src/data/evolutions.ts` の追加で対応可能

## 7. 制約条件

### 技術的制約

- 対応ブラウザ: Chrome / Safari / Firefox / Edge の最新2バージョン
- 対応デバイス: デスクトップ・モバイル（iOS/Android Safari 含む PWA インストール）
- 言語・ランタイム: Node.js 20+（フロント）
- 必須サービス: GitHub Pages、GitHub Actions

### 予算・期間制約

- 月額コスト: GitHub Pages は無料。AWS バックエンドは削除済みのためコスト $0
- 期限: 個人プロジェクトのため明示期限なし

### 法的・規制制約

- 個人情報を一切取得しない（アカウント不要、ログ最小化）
- デジモン公式の意匠・キャラクター名は使用しない（オリジナルタイプ・命名）

## 8. 用語定義

| 用語 | 定義 |
|------|------|
| クリーチャー | プレイヤーが育成する個体。1セーブデータに最大5体（死亡含む） |
| 進化ステージ | タマゴ/ベイビー/チャイルド/アダルト/パーフェクト/アルティメットの6段階 |
| アクティブクリーチャー | 現在操作・時間進行している1体。バトルに自動参加 |
| 墓石 | `isAlive: false` の死亡したクリーチャー。リストに残るが操作不可 |

> 詳細は `docs/glossary.md` を参照。本書には主要用語のみ記載する。

## 9. リスクと対策

| # | リスク | 影響度 | 発生確率 | 対策 |
|---|-------|-------|---------|------|
| R-001 | Service Worker キャッシュで更新が反映されない | 中 | 中 | ビルドハッシュをファイル名に埋め込み、開発時は Application タブで Unregister 運用 |
| R-002 | 進化ロジック変更で既存セーブデータが壊れる | 中 | 中 | スキーマ変更時は後方互換を保ち、移行関数（`migrateLegacyData`）で対応 |
| R-003 | ユーザー描画 SVG による XSS | 中 | 低 | カスタム SVG をエクスポート対象から除外、表示は信頼境界内に限定 |
