## 進化先の分岐（育て方による属性決定 — 2026-06-18 追加）

開始時に属性を選ばせず、**育て方（育成アクションの累計回数）によって進化先タイプが変わる**。

| 項目 | 設計 |
|------|------|
| 開始時 | タイプ選択画面なし。名前のみ入力。誕生時は中立 **Normal** |
| 分岐タイミング | **チャイルド進化（stage1→2）以降、各進化のたびに再判定**（タイプは進化ごとに変わり得る） |
| タマゴ→ベイビー（stage0→1） | 孵化のみ。再判定せず Normal を維持 |
| 判定基準 | 累計 `trainCount` / `playCount` / `feedCount` の「最多アクション＋次点」 |
| タイブレーク | 同数時は `train > play > feed` の優先順位 |
| 全回数0の場合 | Water（バランス）にフォールバック |

### 育て方 → タイプ マッピング

| 最多アクション | 次点アクション | 進化先タイプ |
|----------------|----------------|--------------|
| トレーニング | あそぶ | Fire |
| トレーニング | えさ | Plant |
| あそぶ | トレーニング | Thunder |
| あそぶ | えさ | Light |
| えさ | あそぶ | Water |
| えさ | トレーニング | Dark |

> 実装: `determineTypeFromRaising()`（`frontend/src/utils/evolution.ts`）。`evolveCreature()` が nextStage≥2 で呼び出す。
> 既存セーブのクリーチャー（旧仕様でタイプ確定済み）も、次回以降の進化時はこのロジックで再判定される。

## 進化ステージと条件

| ステージ | 名称 | 進化条件 |
|---------|------|----------|
| 0 | タマゴ | — |
| 1 | ベイビー | タマゴをタップ（即時） |
| 2 | チャイルド | age ≥ 0.5 |
| 3 | アダルト | age ≥ 1, happiness ≥ 50 |
| 4 | パーフェクト | age ≥ 3, level ≥ 8, atk+def+spd ≥ 40 |
| 5 | アルティメット | age ≥ 7, level ≥ 14, 各ステータス ≥ 20 |

> `age` の単位: **日数**。現実時間で **1日 = +1歳**（30分ティックごとに +1/48 の累積、`AGE_PER_TICK`）。表示は `Math.floor(age)` 歳。
> 2026-06-21 変更: 旧仕様（1時間=+1歳・進化条件は時間単位 1/3/6/12）からリアルタイム化。

## 育成アクション

### えさ
- 効果: hunger +30, happiness +5, weight +1（過食時 +3）
- 制限: 睡眠中は不可、**お腹いっぱい（hunger ≥ 100）時は不可**
- **EXP付与なし（意図的な設計）**

### トレーニング（もぐらたたき — 2026-04-10 変更）
- ミニゲーム: 3×3グリッドのもぐらたたき（制限時間8秒、5匹以上で成功）
- 成功: atk/def/spd 各 +1〜3（ランダム）, fatigue +15, EXP +20
- 失敗: atk/def/spd 各 +0〜1（ランダム）, fatigue +15, EXP +5
- 制限: 睡眠中・空腹（hunger ≤ 0）・**疲労MAX（fatigue ≥ 100）時は不可**
- 2026-06-21 変更: おなか消費（hunger -10）を撤廃し、疲労度の蓄積に置き換え

### あそぶ（神経衰弱 — 2026-04-10 変更）
- ミニゲーム: 2×3グリッドの神経衰弱（3ペア、8手以内で成功）
- 成功: happiness +20, fatigue +10
- 失敗: happiness +5, fatigue +10
- **EXP付与なし（意図的な設計）**
- 制限: 睡眠中・空腹（hunger ≤ 0）・**疲労MAX（fatigue ≥ 100）時は不可**
- 2026-06-21 変更: おなか消費（hunger -5）を撤廃し、疲労度の蓄積に置き換え

### ねる
- 睡眠中: HP +ceil(maxHp×0.1) / 30分（2026-04-10 変更: 成長に応じた回復量）
- 制限なし

## 時間更新サイクル（30分ティック）

本番は 30分/ティック、devMode は 30秒/ティック。アプリ非起動中も復帰時に経過ティックをまとめて適用（オフライン追いつき）。

| 条件 | 処理 |
|------|------|
| 毎ティック | hunger -6.25（約8時間で空腹）, happiness -2, age +1/48（現実1日で+1歳）, fatigue -100/6（約3時間で全回復） |
| 睡眠中 | hp +ceil(maxHp×0.1) |
| hunger ≤ 0 | hp -5（餓死ダメージ） |
| hp ≤ 0 | 死亡 → 死亡画面へ（墓石としてリストに残る） |

> 2026-06-21 変更: おなかは**時間経過のみ**で減少（1日3回の食事ペース）。年齢は現実1日で+1歳。疲労度は時間経過で常時回復。

## 疲労度（裏パラメータ）

- `fatigue`（0–100）。プレイヤーには**数値・バーを表示しない**裏パラメータ。
- 蓄積: トレーニング +15 / あそぶ +10。
- 回復: 時間経過で常時回復（30分ティックあたり -100/6、約3時間で全回復）。
- ゲート: `fatigue ≥ 100`（MAX）でトレーニング・あそぶを実行不可（ボタン無効・関数も no-op）。
- 表現: `fatigue ≥ 60` でクリーチャーが「疲労中」モーション（`getAnimationState` が `'tired'` を返す。優先度は hungry の次・sad の前）。
- 互換: 既存セーブ（`fatigue` 欠落）は `fatigue ?? 0` で 0 起点として扱う。

## バトルシステム

### ダメージ計算式

```
baseDamage = attacker.atk * 1.5 - defender.def * (guarding ? 1.6 : 0.8)
typeMod    = TYPE_ADVANTAGE[attacker.type][defender.type]  // 0.8, 1.0, 1.2
spdMod     = attacker.spd > defender.spd ? 1.1 : 0.9
finalDamage = Math.max(1, Math.floor(baseDamage * typeMod * spdMod))
```

| タイプ | 効果 |
|-------|------|
| Fire | 連続2回攻撃（各ダメージ×0.7） |
| Water | 自己回復（maxHp × 0.2）+ 攻撃 |

| Thunder | 麻痺（次ターン行動不可 50%確率） |

クールダウン: 2ターン

### バトル終了条件

| 条件 | 勝者 |
|------|------|
| いずれかのHP ≤ 0 | 相手プレイヤー |
| 10ターン経過 | HP が多い方（同値: 引き分け） |
| 相手が切断 | 残ったプレイヤー |

### バトル後ステータス反映

| 結果 | 変化 |
|------|------|
| 勝利 | wins +1, exp +(50 + 相手level×5), happiness +20 |
| 敗北 | losses +1, exp +10, happiness -10 |
| 引き分け | exp +25 |

HP はバトル終了時の値を維持する。

### CPUバトルモード（2026-04-05 追加）

オンライン対戦に加え、CPU（コンピュータ）対戦モードを追加。WebSocket不要でオフラインで遊べる。

| 項目 | 設計 |
|------|------|
| CPUクリーチャー生成 | プレイヤーの進化段階・ステータスに合わせて自動調整（±10%変動） |
| CPUのタイプ | プレイヤーと異なるタイプからランダム選択 |
| CPUの名前 | 進化系統テーブルから該当ステージの名前を使用 |
| CPUのアクション選択 | 完全ランダム（attack/guard/special 均等、クールダウン中は attack/guard のみ） |
| バトル報酬 | オンライン対戦と同一（勝利: exp +50+相手Lv×5, happiness +20 等） |
| バトル終了条件 | オンライン対戦と同一（HP≤0 or 10ターン経過） |
| ロビーUI | 「CPU対戦」タブ追加。対戦相手のプレビュー表示、相手の変更（再生成）が可能 |

### バトル画面の配置（2026-04-07 変更）

- 自分のクリーチャーを**左側**、相手のクリーチャーを**右側**に配置
- 互いに向き合うようスプライトを反転表示

## クリーチャーお絵描き機能（2026-04-07 追加）

進化のたびにプレイヤーが新しい姿を手書きできる機能。

| 項目 | 設計 |
|------|------|
| 描画タイミング | **進化のたびに1回**（進化演出の後にお絵描き画面を表示） |
| ゲーム開始時 | 描画画面を表示しない（卵から孵化した時点が最初の描画機会） |
| キャンバスサイズ | 64×64 ピクセル（ドット絵風） |
| ツール | ペン / 消しゴム / 塗りつぶし |
| スキップ | 可能（デフォルトスプライトが表示される） |
| 保存形式 | SVG 文字列、ステージ別に保持 |
| 表示サイズ | ステージに応じて100〜300px（ステージが上がるほど大きく表示） |

## 複数クリーチャー管理（2026-04-07 追加）

複数のクリーチャーを同時に所有し、育てたいクリーチャーを選んでプレイできる。

| 項目 | 設計 |
|------|------|
| 最大保有数 | 上限なし |
| クリーチャー切り替え | ステータス画面から選択 |
| 非アクティブの時間経過 | 停止（切り替え時に `lastUpdated` をリセット） |
| 死亡時の扱い | 墓石としてリストに残る（閲覧可・操作不可） |
| バトル出場 | アクティブクリーチャーで自動参加 |
| セーブデータ | 全クリーチャーをまとめて一括保存・エクスポート/インポート |
| 新規クリーチャー追加 | ステータス画面の「＋ 新しいクリーチャーを育てる」ボタン |
